# 中国移动专利技术交底书写作助手

一个可安装到Codex的中文Agent Skill，用于规范化修改专利技术交底书，或通过深度问答完善技术方案、提炼候选保护点。

本项目独立于任何具体专利项目，只包含通用写作方法、案件组织约定和空白模板，不包含真实交底书、实验数据、专家反馈原件或案件历史。由个人维护，用于分享写作工作方法。

## 两种模式

| 模式 | 适合什么任务 | 可以调整什么 | 交付什么 |
|---|---|---|---|
| 规范润色 | 已有方案，需要符合中国移动交底书写作规范 | 全文结构、章节归属、段落顺序、措辞、术语和格式；保持技术内容不变 | 完整小节或全文修改稿、必要的缺口说明；按授权写入 |
| 深度问答 | 方案尚不完整、核心机制不清、需要处理技术审核意见 | 技术问题、实施机制、必要条件、边界和候选保护点，经讨论确认后修改 | 确认方案、待解决问题、术语及决策记录、修改稿 |

技能会尊重用户的手工修改。设计确认、文稿确认、写入文件分别处理，不会因为讨论过一个技术点就自动重写全文。

## 私有仓库共享与访问

本仓库为私有仓库，仅有权限的GitHub账号可以查看和下载。仓库所有者可在[访问管理页面](https://github.com/yuewangnb-eng/cmcc-patent-disclosure/settings/access)邀请协作者；受邀者需要先接受邀请。

安装前先登录自己的GitHub账号，确认能在浏览器打开本仓库。命令行或助手安装时也需要具备该账号的仓库访问权限；只在浏览器登录不代表命令行已完成认证。遇到“Repository not found”或404时，先检查账号、邀请状态和命令行认证。

不使用命令行的协作者，可以在已登录的浏览器中下载ZIP，再按下面的手动安装说明放入技能目录。不要在提示词、Issue或文档中粘贴访问令牌。

## 安装

需要一个支持本地Agent Skills的AI助手。以下以Codex为例；本项目本身没有运行程序，不需要安装Python、Node.js或设置API密钥。模型服务、文件访问和联网能力由使用的AI助手提供。

### 方式一：让Codex安装

把以下内容发给Codex：

```text
使用$skill-installer，从https://github.com/yuewangnb-eng/cmcc-patent-disclosure安装技能。
SKILL.md位于仓库根目录，技能名称是cmcc-patent-disclosure。
```

如果提示已安装同名技能，先核对已有版本及本地修改，再更新，不要直接覆盖个人定制。

### 方式二：手动安装

克隆整个仓库到用户技能目录。以下命令仅适用于目标目录尚不存在的首次安装。

**Windows PowerShell：**

```powershell
$skillParent = Join-Path $env:USERPROFILE '.agents/skills'
New-Item -ItemType Directory -Path $skillParent -Force | Out-Null
git clone https://github.com/yuewangnb-eng/cmcc-patent-disclosure.git (Join-Path $skillParent 'cmcc-patent-disclosure')
```

**macOS / Linux：**

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/yuewangnb-eng/cmcc-patent-disclosure.git ~/.agents/skills/cmcc-patent-disclosure
```

也可在GitHub选择 **Code → Download ZIP**，解压后把包含`SKILL.md`的目录命名为`cmcc-patent-disclosure`，放入个人技能目录。不要只复制`SKILL.md`，必须保留`references/`和`assets/`。

仅供一个项目使用时，可以放到该项目的`.agents/skills/cmcc-patent-disclosure/`。只选择一种安装位置，避免同名技能重复显示。

Codex会自动发现技能；未显示时重新启动Codex。在技能列表中选择“中国移动专利技术交底书写作助手”，或使用`$cmcc-patent-disclosure`。安装目录和发现方式参见[OpenAI官方技能说明](https://learn.chatgpt.com/docs/build-skills)。若客户端采用其他技能目录，以其配置为准。

## 快速开始：规范润色

准备当前交底书，提供术语约定或术语表；没有独立术语表也可以开始，助手会识别正文已有定义。写作规范和空白模板已经内置。

在助手能够访问文稿的项目中发送：

```text
使用$cmcc-patent-disclosure，进入规范润色模式。
当前主稿是我提供的交底书，术语按随附术语表执行。
先检查全文结构是否符合内置规范，再修改第五部分。
可以调整章节归属、段落顺序和文字表达，保持技术机制和判断条件不变。
先给我完整修改稿，确认后再写入文件。
```

需要直接修改时，可以明确授权：

```text
使用$cmcc-patent-disclosure，规范润色当前交底书的第三、四部分并写入。
保留技术含义和所有必要条件，写入前重新读取文件，完成后说明差异。
技术内容有缺口时列出问题，不自行补充。
```

默认以完整小节为单位处理。若希望先看审查意见，可要求“先呈现完整原文并标注问题，给修改意见，暂不生成修改稿”。

## 快速开始：深度问答

深度问答会先读材料，再围绕有依赖关系的问题分轮讨论。它不会固定问一套长问卷，也不会把资料中能查到的事实全部交给用户回答。

```text
使用$cmcc-patent-disclosure，进入深度问答并记录模式。
工作目录是我当前打开的案件目录，主稿和术语表已提供。
先检查技术主线和实施缺口，再与我逐轮讨论，提炼候选核心保护点。
允许维护技术方案工作记录和术语表；交底书正文确认后再写入。
如果grill-with-docs及其依赖未安装，允许直接按本技能内置的深度问答流程继续。
```

只讨论一个技术点也可以：

```text
使用$cmcc-patent-disclosure，深度讨论当前步骤。
重点检查输入输出、必要条件、失败后的处理，以及这一步是否为核心机制所必需。
本轮只在对话中讨论，不创建或修改任何文件。
外部问答技能不可用时，按本技能内置流程继续。
```

### grill-with-docs依赖说明

- 规范润色不依赖其他问答技能。
- 深度问答可联动`grill-with-docs`，后者组合`grilling`与`domain-modeling`。需要联动时，这三个技能应可被助手发现。
- 本仓库不打包这些外部技能，也不自动下载或安装。可以使用所在环境已安装的版本。
- 本仓库的[深度问答流程](references/深度问答.md)包含可独立执行的问题组织、术语澄清和记录方法。未安装外部技能时，在提示中明确允许使用内置流程即可，助手不会声称已经调用外部技能。
- 如果你要求必须使用`grill-with-docs`，而环境中没有它，助手会说明缺失并等待处理。

## 问答记录存在哪里

技能代码与案件工作区分开：**不要把真实交底书或案件记录保存到这个共享仓库。**

已有案件优先复用现有目录和同职责文件，不自动搬迁。新案件按实际需要逐步建立：

```text
案件目录/
├── README.md                         # 当前主稿和工作入口
├── 写作术语表.md                     # 标准称谓、定义与使用边界
├── 01_原始资料/                      # 原始需求和项目材料，只读保留
├── 02_检索与对比/                    # 文献索引、原文、批次与当前对照
├── 03_技术方案与证据/
│   ├── 方案确认/技术方案工作记录.md  # 当前方案、未决问题、保护点、决定和落实
│   ├── 研发与验证记录/              # 已有结果与待执行计划分别标明
│   └── 附图/                        # 图源与导出图分别保存
├── 04_交底书/                        # Markdown主稿、按需导出件和版本索引
├── 05_提案与审核/                    # 按实际提交次数保存提交包和审核记录
├── 90_工具/                          # 项目实际使用的工具
└── 99_历史版本/                      # 历史稿，只读追溯
```

只提供一份交底书也能开始，不必先创建全部目录。完整目录、每个文件应写什么，以及何时更新，见[深度问答：案件工作区约定](references/深度问答.md#三案件工作区约定)。

“深度问答并记录”允许持续维护方案工作记录和术语表，不自动授权修改主稿、图示或全部索引。恢复讨论时，助手先读当前入口和工作记录，不需要重新粘贴全部聊天。

## 什么时候会修改文件

| 你的要求 | 助手行为 |
|---|---|
| 只审查、只讨论、先给修改稿 | 在对话中输出，不写入正文 |
| 深度问答并记录 | 在指定案件中维护确认结果、待解决问题和术语 |
| 落稿、写入，或明确授权直接修改 | 重新读取文件，修改已授权内容并核对差异 |
| 导出Word或生成图片 | 使用主稿及模板完成指定格式工作，检查对应关系 |

不会自动升版、改名、提交或推送Git，也不会自动发送给他人。原始材料、冻结提交包、专家原件和历史版本保留不动。

## 模板与导出

[中国移动技术交底书空白模板](assets/中国移动技术交底书模板.doc)随技能提供。用户提供新版或单位指定版本时，优先采用指定版本。本项目不把配套模板宣称为始终最新的版本。

本仓库提供写作和排版规则，**没有跨平台Word导出程序**。普通Markdown润色不需要Microsoft Word；读取旧版`.doc`模板或生成Word时，需要助手环境提供相应文档工具。若无法使用，助手应说明限制，不能声称已完成导出。

## 更新与反馈

通过Git克隆安装后，先确认没有个人未保存修改，再在安装目录执行：

```bash
git status --short
git pull --ff-only
```

如果已经自行修改技能，先保留并比较修改，不使用强制覆盖命令。通过ZIP或安装器安装的版本，可重新下载后比较更新。

欢迎通过Issue或Pull Request反馈通用规则、表达或安装问题。请提供经过脱敏的最小示例，不上传真实交底书、人员联系方式、未公开技术方案或内部文件。改进通用方法时，不把某个具体案件的决定变成所有案件都必须遵守的规则。
