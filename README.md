# CMCC专利技术交底书写作助手

一套面向CMCC专利交底书写作的通用智能体的中文Agent Skill，用于规范化修改专利技术交底书，或通过深度问答完善技术方案、提炼候选保护点。

## 两种模式

| 模式 | 适合什么任务 | 可以调整什么 | 交付什么 |
|---|---|---|---|
| 规范润色 | 已有方案，需要符合CMCC交底书写作规范 | 全文结构、章节归属、段落顺序、措辞、术语和格式；保持技术内容不变 | 完整小节或全文修改稿、必要的缺口说明；按授权写入 |
| 深度问答 | 方案尚不完整、核心机制不清、需要处理技术审核意见 | 技术问题、实施机制、必要条件、边界和候选保护点，经讨论确认后修改 | 确认方案、待解决问题、术语及决策记录、修改稿 |

技能会尊重用户的手工修改。设计确认、文稿确认、写入文件分别处理，不会因为讨论过一个技术点就自动重写全文。


## 安装与加载

本项目由Markdown指令、参考文档和空白模板组成，不绑定特定智能体产品。本身没有运行程序，不需要安装Python、Node.js或配置API密钥；模型服务及工具能力由使用的智能体环境提供。

### 方式一：使用支持Agent Skills的智能体

向具备仓库访问和技能安装能力的智能体发送：

```text
请从https://github.com/yuewangnb-eng/cmcc-patent-writing-assistant加载或安装技能。
SKILL.md位于仓库根目录，技能标识是cmcc-patent-writing-assistant。
请使用当前智能体环境支持的技能安装位置和加载方式，保留references和assets目录。
如已有同名技能，先核对本地修改，不直接覆盖。
```

不同智能体的技能目录、安装器和调用语法可能不同，按所用环境的说明操作。本项目不要求固定安装路径、专用安装技能或统一的调用前缀。

### 方式二：手动下载技能目录

在本地选择一个存放技能的目录，执行以下命令；目标目录需尚不存在：

```bash
git clone https://github.com/yuewangnb-eng/cmcc-patent-writing-assistant.git cmcc-patent-writing-assistant
```

也可在GitHub选择 **Code → Download ZIP**，解压后保留完整目录。不要只复制`SKILL.md`，`references/`和`assets/`也需要保留。

将该目录导入智能体的技能管理功能，或放入该环境明确支持的技能目录。需要刷新或重新加载时，遵循该环境的操作方式，不假设所有智能体都会自动发现文件。

### 方式三：不支持原生技能时，作为工作指令使用

向智能体提供以下文件：

- 入口：[SKILL.md](SKILL.md)。
- 规范润色：[写作规范](references/写作规范.md)。
- 深度问答：[深度问答](references/深度问答.md)；需要起草正文时一并提供写作规范。

可以上传文件、加入项目上下文或粘贴相关内容，再说明：

```text
请按我提供的“CMCC专利技术交底书写作助手”指令工作。
本轮使用规范润色模式。先读取入口文件及写作规范，再处理我提供的交底书。
如果当前环境无法读取或修改文件，请在对话中给出完整修改稿，并明确尚未写入文件。
```

这里的“提供文件”指交给你选择的智能体环境。请按自己的资料使用权限选择环境；本技能不会自动把案件材料上传到本仓库。

### 所需能力

| 任务 | 智能体需要具备的能力 |
|---|---|
| 规范审阅、问答、输出修改稿 | 能读取提供的指令与正文并进行多轮对话 |
| 自动读取案件目录、维护记录和修改主稿 | 相应文件访问工具及用户授权 |
| 核对外部文献 | 联网检索或读取用户提供原文的能力 |
| 读取旧版模板、生成Word或图片 | 支持相应格式的文档或绘图工具 |

缺少工具时仍可完成适用的文字工作，但不能声称已经执行文件保存、检索或导出。本项目不宣称已在所有智能体产品中完成兼容性测试。

## 快速开始：规范润色

准备当前交底书，提供术语约定或术语表；没有独立术语表也可以开始，助手会识别正文已有定义。写作规范和空白模板已经内置。

在助手能够访问文稿的项目中发送：

```text
使用“CMCC专利技术交底书写作助手”（cmcc-patent-writing-assistant），进入规范润色模式。
当前主稿是我提供的交底书，术语按随附术语表执行。
先检查全文结构是否符合内置规范，再修改第五部分。
可以调整章节归属、段落顺序和文字表达，保持技术机制和判断条件不变。
先给我完整修改稿，确认后再写入文件。
```

需要直接修改时，可以明确授权：

```text
使用“CMCC专利技术交底书写作助手”（cmcc-patent-writing-assistant），规范润色当前交底书的第三、四部分并写入。
保留技术含义和所有必要条件，写入前重新读取文件，完成后说明差异。
技术内容有缺口时列出问题，不自行补充。
```

默认以完整小节为单位处理。若希望先看审查意见，可要求“先呈现完整原文并标注问题，给修改意见，暂不生成修改稿”。

## 快速开始：深度问答

深度问答会先读材料，再围绕有依赖关系的问题分轮讨论。它不会固定问一套长问卷，也不会把资料中能查到的事实全部交给用户回答。

```text
使用“CMCC专利技术交底书写作助手”（cmcc-patent-writing-assistant），进入深度问答并记录模式。
工作目录是我当前打开的案件目录，主稿和术语表已提供。
先检查技术主线和实施缺口，再与我逐轮讨论，提炼候选核心保护点。
允许维护技术方案工作记录和术语表；交底书正文确认后再写入。
如有grill-with-docs可联动使用；没有时按本技能内置的深度问答流程继续。
```

只讨论一个技术点也可以：

```text
使用“CMCC专利技术交底书写作助手”（cmcc-patent-writing-assistant），深度讨论当前步骤。
重点检查输入输出、必要条件、失败后的处理，以及这一步是否为核心机制所必需。
本轮只在对话中讨论，不创建或修改任何文件。
外部问答技能不可用时，按本技能内置流程继续。
```

### 可选的grill-with-docs联动

- 两个模式都提供可独立执行的流程，不强制安装其他问答技能。
- 深度问答可联动`grill-with-docs`，后者组合`grilling`与`domain-modeling`。需要联动时，这三个技能应可被助手发现。
- 本仓库不打包这些外部技能，也不自动下载或安装。可以使用所在环境已安装的版本。
- 本仓库的[深度问答流程](references/深度问答.md)包含可独立执行的问题组织、术语澄清和记录方法。未安装外部技能时默认使用内置流程，助手会说明所采用的方式，不会声称已经调用外部技能。
- 如果你要求必须使用`grill-with-docs`，而环境中没有它，助手会说明缺失并等待处理。

## 问答记录存在哪里

技能代码与案件工作区分开：**不要把真实交底书或案件记录保存到这个共享仓库。**

已有案件优先复用现有目录和同职责文件，不自动搬迁。新案件按实际需要逐步建立：

```text
案件目录/
├── README.md                         # 当前主稿和工作入口
├── 写作术语表.md                     # 标准称谓、定义与使用边界
├── 01_原始资料/                      # 原始需求和项目材料，只读保留
├── 02_检索与对比/                    # 文献索引、原文、批次与当前对照
├── 03_技术方案与证据/
│   ├── 方案确认/技术方案工作记录.md  # 当前方案、未决问题、保护点、决定和落实
│   ├── 研发与验证记录/              # 已有结果与待执行计划分别标明
│   └── 附图/                        # 图源与导出图分别保存
├── 04_交底书/                        # Markdown主稿、按需导出件和版本索引
├── 05_提案与审核/                    # 按实际提交次数保存提交包和审核记录
├── 90_工具/                          # 项目实际使用的工具
└── 99_历史版本/                      # 历史稿，只读追溯
```

只提供一份交底书也能开始，不必先创建全部目录。完整目录、每个文件应写什么，以及何时更新，见[深度问答：案件工作区约定](references/深度问答.md#三案件工作区约定)。

“深度问答并记录”允许持续维护方案工作记录和术语表，不自动授权修改主稿、图示或全部索引。恢复讨论时，助手先读当前入口和工作记录，不需要重新粘贴全部聊天。

## 什么时候会修改文件

| 你的要求 | 助手行为 |
|---|---|
| 只审查、只讨论、先给修改稿 | 在对话中输出，不写入正文 |
| 深度问答并记录 | 在指定案件中维护确认结果、待解决问题和术语 |
| 落稿、写入，或明确授权直接修改 | 重新读取文件，修改已授权内容并核对差异 |
| 导出Word或生成图片 | 使用主稿及模板完成指定格式工作，检查对应关系 |

不会自动升版、改名、提交或推送Git，也不会自动发送给他人。原始材料、冻结提交包、专家原件和历史版本保留不动。

## 模板与导出

[CMCC技术交底书空白模板](assets/CMCC技术交底书模板.doc)随技能提供。用户提供新版或单位指定版本时，优先采用指定版本。模板中的展示名称已统一为CMCC；填写要求和章节结构保留。本项目不把配套模板宣称为始终最新的版本。

本仓库提供写作和排版规则，**没有跨平台Word导出程序**。普通Markdown润色不需要Microsoft Word；读取旧版`.doc`模板或生成Word时，需要助手环境提供相应文档工具。若无法使用，助手应说明限制，不能声称已完成导出。

## 更新与反馈

通过Git克隆安装后，先确认没有个人未保存修改，再在安装目录执行：

```bash
git status --short
git pull --ff-only
```

如果已经自行修改技能，先保留并比较修改，不使用强制覆盖命令。通过ZIP或安装器安装的版本，可重新下载后比较更新。

欢迎通过Issue或Pull Request反馈通用规则、表达或安装问题。请提供经过脱敏的最小示例，不上传真实交底书、人员联系方式、未公开技术方案或内部文件。改进通用方法时，不把某个具体案件的决定变成所有案件都必须遵守的规则。
